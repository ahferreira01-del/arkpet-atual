============================================================

1. PROBLEMA DE CONCORRÊNCIA
   ============================================================

A estratégia anterior de lock
por:

crecheId
+
tutorId
+
período

NÃO é suficiente.

Motivo:

uma cobrança pode nascer
matematicamente no período A,

descobrir que A está congelado

e ser redirecionada
para a sucessora B.

Ao mesmo tempo,
outra cobrança pode nascer
diretamente no período B.

Se os locks forem
por período:

request 1
pode possuir lock A

enquanto:

request 2
possui lock B.

As duas podem então
tentar criar a mesma
fatura sucessora B.

============================================================
2. REGRA AUTORITATIVA
=====================

A resolução da fatura coletora
deve ser serializada por:

CRECHE
+
TUTOR

e NÃO por período.

============================================================
3. LOCK SCOPE
=============

O lock transacional deve cobrir
TODA a operação:

1. receber cobrança;

2. identificar creche/tutor;

3. adquirir lock;

4. calcular ciclo normal;

5. procurar collector editável;

6. detectar fatura congelada;

7. avançar para próximo período;

8. calcular sucessora;

9. procurar sucessora existente;

10. criar sucessora se necessário;

11. adicionar lançamento;

12. atualizar total;

13. concluir transaction.

============================================================
4. LOCK MUST COME BEFORE
PERIOD RESOLUTION
=================

Não fazer:

calculate period

→ choose successor

→ acquire lock.

Preferir:

begin transaction

→ acquire tutor/creche lock

→ resolve period

→ resolve successor

→ get/create invoice

→ add charge

→ commit.

============================================================

=======================

25. COLLECTOR ALGORITHM
=======================

Dentro do lock:

calculateCycle(chargeDate)

LOOP:

candidate =
findEditableInvoice(

tutorId,
period
)

if candidate exists:
return candidate

closedInvoice =
findFrozenInvoice(
crecheId,

period.dueDate < businessDate

if closedInvoice exists

nextApplicablePeriod(period)

else:

with:
crecheId
tutorId
cycleStart
cycleEnd
dueDate

```
return invoice
```
